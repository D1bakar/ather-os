Mission

Aether OS exists to explore what a modern general-purpose kernel looks like when security is a first-class design constraint—not a patch cycle after the fact. We build in Rust for memory safety at the crate boundary, document every significant decision as a numbered ADR, and ship only what we can verify: serial output in QEMU, host tests in CI, checksums in a release manifest.

This is systems research infrastructure. It is not a daily-driver OS, a consumer product, or a browser demo with a fake desktop.

Two products, one artifact chain

Aether is developed as two coupled surfaces over identical boot artifacts:

  • Aether OS — Rust kernel, UEFI boot loader, user runtime. Target: x86_64 with OVMF. Verified runtime: QEMU + COM1 serial.
  • Aether Web (Universal Platform) — Static delivery of the same BOOTX64.EFI and kernel.elf with manifest integrity. Phase 1 ships the pipeline; Phase 2 targets in-browser boot via qemu.wasm.

We explicitly rejected parallel BIOS boot paths and simulated OS UIs that would fork the kernel for web demos. See ADR-0010.

Team philosophy

  • Evidence over narrative. Milestones close when CI or QEMU proves them—not when slides look good.
  • Honest ledgers. Planned work is labeled planned. Scaffolds are not shipped features.
  • ADR-governed architecture. Significant changes require a written decision record.
  • Open source by default. MIT license. Public development on GitHub.
  • Security-first, fail-closed. Capability model, syscall validation, threat model—all documented before scale.
